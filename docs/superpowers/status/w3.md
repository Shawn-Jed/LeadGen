## Zustandsmaschine (W3.1) — `backend/prototyp.py`
`none → pending → draft_ready → approved_local → published` (+ `rework`, `archived`).
Migration Alt-Wert `ready`: mit URL → `published`, ohne → `draft_ready` (in-memory, kein Disk-Write).
Übergangs-Funktionen mit Vorbedingung: `approve_local` nur aus `draft_ready`, `mark_published`
nur aus `approved_local`. Legacy `mark_ready` bleibt als Kompat-Alias.

## Ein Auftrag, zwei Ausgabewege (W3.2) — `backend/app.py`, `frontend/app.js`
- `POST …/prototyp/draft` speichert HTML **lokal** → `draft_ready`, **deployt nicht mehr**.
- Neue Endpunkte: `…/approve`, `…/publish`, `…/rework`, `…/archive`. Lead-State wird um
  `prototyp_state` angereichert; Cockpit zeigt pending/draft_ready/rework/published.
- Prompt-Export/„Design-Prompt kopieren" bleibt als markierter manueller Fallback.

## Freigegebener Publish (W3.6) — `backend/app.py` + `backend/deploy.py`
`…/prototyp/publish` prüft `approved_local`, ruft `deploy.deploy(...)` (injizierbar) und setzt
`published` + URL. **Tests mit Fake-Pusher, kein echter Git-Push.** Kein Außenwirkungsschritt in
dieser Welle ausgeführt.
